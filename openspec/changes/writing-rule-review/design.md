# Design

`prepare` emits a stable five-task plan inside verification, so `verification_sha256` binds the plan. The accepted human-review artifact may include a `rule_review` report bound to the plan and both texts; the existing artifact envelope also binds proposal/verification and is retained by manifest digest. The service verifies exact quoted spans and complete coverage before accepting an APPROVED report, then stores the validated reviewer report in the immutable writing bundle. A current-version review without the optional report remains `not_run`; previously accepted bundles are not rewritten. A pending pre-change review has a stale verification digest and must be regenerated. Semantic checks remain advisory. The existing preservation/fact-lock mechanisms alone can reject automatically. No provider invocation, scheduler or detector quality inference is added.
