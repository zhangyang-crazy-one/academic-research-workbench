## Why

Issues #115 and #116 report real startup friction and versioned literature intake gaps. A broad research direction needs a stable, resumable project before paper narrative selection, and external direction content needs mechanical provenance checks without being treated as scientific authority.

## What Changes

- Expose stable project initialization in core, retaining memory init-project compatibility.
- Add research start/status/resume with reviewable immutable requests, existing run ledger, interruption recovery and layered state.
- Add bounded external direction-package inspect/bind/check/intake preparation, delegating profile/branch, AcceptedRef, citation and experiment replay to existing validators.
- Provide synthetic interpretive/computational packages and an offline versioned-literature walkthrough; preserve all unresolved and negative states.

## Capabilities

### New Capabilities
- `research-startup`: Core project administration and resumable, project-bound scoping startup.
- `research-direction-package`: External direction contracts, cross-stage binding checks and versioned intake preparation.

### Modified Capabilities
None. Existing narrative selection, scientific admission, citation replay and publication authority continue to enforce their contracts.

## Impact

Core project identity helpers, CLI/launcher, optional thin package composition, request models, targeted crash/conflict tests, two main skills and runtime examples. No new model client, dependency, automatic installation or canonical ledger.
