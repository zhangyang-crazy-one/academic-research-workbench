## Why

The formal release gate correctly rejects self-asserted approval, but no independently verifiable owner authorization exists. v0.2.0 needs actual candidate-bound qualification and an authenticated declaration before publication.

## What Changes

- Add an owner-dispatched GitHub Actions OIDC authority for exact successful main CI subjects and the qualified bundle.
- Bind live repository/run/artifact/draft/asset identity and permission inventory; reject substitution, unknown use, reruns and unsupported commercial grants.
- Transfer actual Phase 7 qualification through one exact-source draft asset without changing original CI bytes.
- Require technical checks before signing and independent cryptographic verification before publishing the existing draft.
- Keep historical blocked records immutable. Forward explicit qualification paths to strict tests and pin fresh-home native Codex calls to gpt-6.1-sol/high.

## Capabilities

### New Capabilities
- `authenticated-release-authority`: Independently signed, exact-candidate owner declaration with bounded publication.

### Modified Capabilities
None.

## Impact

Maintainer-only policy/schema/scripts, release workflows, qualification environment and regression tests. Native platform authentication is reused; no model API keys or new runtime dependencies are introduced.
