<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| contract producer → parent runtime | Untrusted assignment/proposal/review/hook fields cross into future canonical validation. |
| parent-only sealed corpus → worker fixtures | Evaluation labels must not cross into assignments or prompts. |
| checked-in schema/corpus → evaluator | Tampered bytes could silently change accepted authority or expected verdicts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01 | Spoofing | role and host identity contracts | mitigate | Frozen role IDs, explicit execution modes, distinct identity fields, and schema tests reject missing or substituted identity evidence. |
| T-04-02 | Tampering | schemas and corpus manifest | mitigate | Canonical JSON, checked-in generated schemas, SHA-256 manifest entries, and digest regeneration tests. |
| T-04-03 | Information disclosure | sealed corpus | mitigate | Keep labels solely under `sealed-parent-only`; test every worker-visible projection for absence of those labels. |
| T-04-04 | Repudiation | gate and human-decision records | mitigate | Require actor, rationale, applicable transition, evidence digest, subject, scope, and canonical bytes in strict contracts. |
| T-04-05 | Denial of service | output and corpus inputs | mitigate | Encode output byte limits and fixed corpus sizes before dispatch code exists. |
| T-04-06 | Elevation of privilege | deferred executor roles | mitigate | Reject `code_runner` and `study_manager`; retain `experiment_designer` as proposal-only per D-03. |
| T-04-SC | Tampering | package-manager installs | mitigate | No package-manager install is permitted in this phase; verify `uv.lock` is unchanged and no package legitimacy exception is introduced. |
</threat_model>
