## Locked Decision Trace

- D-01: The versioned role catalog is a contract, not host configuration.
- D-02: `native_profile` and `assignment_injected_subagent` are distinct formal-capable modes only with host identity/isolation proof; only truly inline work is `degraded_inline`, and an unavailable required independent role is `blocked`.
- D-03: `experiment_designer` is proposal-only, distinct from `methodology_reviewer`; execution adapters remain excluded.
- D-04: The immutable conflict matrix rejects prohibited shared identities.
- D-05: Assignments bind all authority inputs and content changes supersede rather than mutate.
- D-06: The frozen DAG key is part of the assignment contract.
- D-07: Retry eligibility and the two-attempt ceiling are data, not scheduler discretion.
- D-08: Cancellation, stale evidence, and orphan interruption have explicit immutable states.
- D-09: The catalog contains the four required reviewer roles and a separate synthesizer.
- D-10: Blind-envelope bindings prohibit peer identity and report visibility.
- D-11: Required versus optional role policy and limitations are frozen inputs.
- D-12: Finding-matrix classifications preserve dissent and unresolved critical blockers.
- D-13: Hook trust status is an observation contract with authority parity fields.
- D-14: Continuation counters are bounded observations, never acceptance authority.
- D-15: Gate decisions bind rationale-bearing human-trigger conditions and fresh evidence.
- D-16: Human decisions are append-only, scoped records and cannot rewrite verdict history.

## Trust Boundaries

| Boundary | Description |
|---|---|
| contract producer → parent runtime | Untrusted assignment/proposal/review/hook fields cross into future canonical validation. |
| parent-only sealed corpus → worker fixtures | Evaluation labels must not cross into assignments or prompts. |
| checked-in schema/corpus → evaluator | Tampered bytes could silently change accepted authority or expected verdicts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-04-01 | Spoofing | role and host identity contracts | mitigate | Frozen role IDs, explicit execution modes, distinct identity fields, and schema tests reject missing or substituted identity evidence. |
| T-04-02 | Tampering | schemas and corpus manifest | mitigate | Canonical JSON, checked-in generated schemas, SHA-256 manifest entries, and digest regeneration tests. |
| T-04-03 | Information disclosure | sealed corpus | mitigate | Keep labels solely under `sealed-parent-only`; test every worker-visible projection for absence of those labels. |
| T-04-04 | Repudiation | gate and human-decision records | mitigate | Require actor, rationale, applicable transition, evidence digest, subject, scope, and canonical bytes in strict contracts. |
| T-04-05 | Denial of service | output and corpus inputs | mitigate | Encode output byte limits and fixed corpus sizes before dispatch code exists. |
| T-04-06 | Elevation of privilege | deferred executor roles | mitigate | Reject `code_runner` and `study_manager`; retain `experiment_designer` as proposal-only per D-03. |
| T-04-SC | Tampering | package-manager installs | mitigate | No package-manager install is permitted in this phase; verify `uv.lock` is unchanged and no package legitimacy exception is introduced. |
</threat_model>
