## Trust Boundaries

| Boundary | Description |
|---|---|
| manifest/definition to reducer | A changed workflow definition could rewrite historical legality. |
| event actor metadata to authority table | A worker/hook could impersonate an authorized canonical actor. |
| reducer state to status renderers | Independent renderer logic could report a different workflow truth. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-02-01 | Tampering | workflow definition | mitigate | Canonical definition digest bound to new manifests; immutable legacy mapping and hash tests. |
| T-02-02 | Spoofing/Elevation | actor authority | mitigate | Strict actor role plus category matrix; worker/hook rejection tests. |
| T-02-03 | Tampering/Repudiation | reducer | mitigate | Pure exhaustive state tests and forbidden unknown/out-of-order events. |
| T-02-04 | Information Disclosure/Tampering | status | mitigate | Shared strict model, no writes, stable fields only, tree-snapshot tests. |
</threat_model>
